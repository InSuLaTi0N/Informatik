= Test-Plan
:toc: macro
:toc-title:

Dieser Testplan stellt eine vereinfachte Version der IEEE 829-1998 Vorlage dar.

[discrete]
== Inhaltsverzeichnis

toc::[]

== 1. Einführung
Dieser Test-Plan soll sicherstellen, dass alle Komponenten, die im Rahmen des Projekts "Papa Pizza"
erstellt werden, bei Fertigstellung voll funktionsfähig sind und den Erwartungen des Kunden
entsprechen. Dafür werden Integrations- und Unit-Tests erstellt und
ausgewertet.

== 2. Aufbau der Testbezeichner
Die Testbezeichner beginnen alle entweder mit dem Präfix *U* für Unit-Test oder dem Präfix
*I* für Integrationstest. Anschließend folgen drei Ziffern, bei denen die erste jeweils für
eine Komponente steht. Dabei steht *1* für Customer, *2* für Employee, *3* für MyOrder, *4* für
Catalog und *5* für Branch. Die übrigen zwei Ziffern werden zur Unterscheidung der
einzelnen Tests für die jeweilige Komponente eingesetzt.

== 3. Testgegenstände
* Customer
* Employee
* Order
* Catalog
* Branch

== 4. Zu testende Funktionalitäten
=== 4.1 Customer
* Customer hinzufügen/bearbeiten/löschen
* Ausgabe der Customer
* Fehlermeldung bei falschen Eingaben oder invaliden Aktionen, wie Accounts doppelt vergeben
* TAN/Token-System

=== 4.2 Employee
* Employee hinzufügen/bearbeiten/löschen
* Ausgabe der Employees
* Fehlermeldung bei falschen Eingaben oder invaliden Aktionen, wie Accounts doppelt vergeben
* Besonderheiten im Verhalten der 'ADMIN'-Rolle

=== 4.3 Order
* MyOrder erstellen
* Produkte zu einer MyOrder hinzufügen
* Status von MyOrder/OrderLine ändern
* MyOrder/OrderLines nach Status anzeigen

=== 4.4 Catalog
* Produkte bearbeiten/hinzufügen/löschen
* Fehlermeldung bei falschen Eingaben
* Ausgabe von Produkten aus dem Catalog

=== 4.5 Branch
* Korrektheit der automatisch erstellten AccountancyEntrys
* Ausgabe der Abrechnung

== 5. Nicht zu testende Funktionalitäten
Alle Funktionalitäten, die aus Spring oder Salespoint übernommen werden, müssen nicht
getestet werden, da davon auszugehen ist, dass diese bereits ausreichenden Test unterzogen
wurden. Allerdings sollten sie in die Tests mit einbezogen werden, um ein fehlerfreies
Zusammenspiel sicherzustellen.

== 6. Herangehensweise
Es werden möglichst viele Funktionalitäten mittels JUnit getestet. Zuerst werden
einzelne Funktionen getestet und anschließend immer komplexere und größere
funktionale Einheiten. Hier kommen Integrationstest hinzu. Das Bottom-Up Prinzip
dient beim gesamten Prozess als Leitlinie.

== 7. Umgebungsvoraussetzungen
Um die Tests durchzuführen, wird ein Computer benötigt, der keine besonderen Kriterien
erfüllen muss aber dem heutigen Stand der Technik entsprechen sollte. Ferner werden
Eingabemöglichkeiten benötigt. Eingaben können sowohl mit Touchscreen als auch mit Maus und Tastatur
erfolgen. Eine Internetverbindung ist wünschenswert aber nicht zwingend erforderlich.
Alle für die Tests erforderlichen Daten, sowie die Tests selbst, befinden sich im Repository des
Projekts, welches über das Internet oder lokal über einen Datenträger zur Verfügung gestellt werden
kann.

Zum Ausführen der Tests wird Java mindestens in der Version 11 benötigt. Eine dazu passende
IDE (wie vorzugswiese IntelliJ, anderenfalls Eclipse, VS Code, etc) ist wünschenswert.

Zum Testen der ausgeführten Anwendung wird einer der folgenden Browser benötigt:

* Firefox 4.0
* Internet Explorer / Edge 10.0
* Chrome 4.0
